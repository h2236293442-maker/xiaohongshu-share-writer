# Xiaohongshu Share Writer

用于把一篇文章、一个主题、一个链接、几张参考图或一段笔记，整理成可直接发布的小红书分享稿。

适用场景：
- 用户给出文章链接、文档、截图、主题，想做成小红书多页分享
- 用户需要封面标题、导读页、详情页、总结页
- 用户需要小红书发布标题、正文、标签
- 用户需要配图提示词，尤其是英文版、统一风格、无文字插图 prompt

不适用场景：
- 纯技术实现、代码生成、调试问题
- 与小红书内容策划无关的普通问答

## 默认产出

当用户没有指定格式时，默认输出以下内容：

1. 封面标题候选
2. 导读页文案
3. 逐页内容策划
4. 每页标题、正文、总结
5. 每页插图提示词（英文）
6. 小红书发布标题
7. 小红书发布正文
8. 推荐标签

## 默认内容结构

优先采用适合小红书阅读节奏的多页结构：

1. `P1 封面`
2. `P2 导读`
3. `P3-Pn 详情页`
4. `最后1页 总结页`

默认优先控制在 `6-8 页`，保证信息密度和排版节奏平衡；如果用户没有特别说明，不默认拉得太长。

如果用户已经指定页数或顺序，严格按用户要求来。

## 默认版式规则

### 1. 封面页

目标：
- 用结果感、冲突感或反差感做钩子
- 默认只保留一个封面标题，不写副标题；除非用户明确要求加副标题
- 封面标题默认不要太短，优先控制在约 18-22 个中文字符，保证有信息量和钩子感
- 标题优先按 2-4 行排版，避免一行塞满或断句别扭
- 封面页默认不放插图，除非用户明确要求

写法建议：
- 优先用“为什么 / 别再 / 不是...而是... / 从...到...”这类钩子
- 标题要兼顾信息量和排版感，避免过短显空、过长显挤、断句别扭、信息过载

### 2. 导读页

默认采用固定结构：
- `标题`
- `第一段`
- `第二段`
- `一句收口`

要求：
- 标题简短，通常 8-14 字
- 两段正文解释“为什么值得看”和“这一篇会讲什么”
- 收口一句做方法论总结
- 导读页默认不放插图，除非用户明确要求

### 3. 详情页

默认采用固定结构：
- `标题`
- `内容`
- `总结`
- `插图提示词`

其中：
- `内容`：默认控制在 1-2 句短内容，讲清概念或作用即可，不要写成长段大段解释
- `总结`：固定三点式，每点 1 行，突出方法名、术语名、落地点
- `插图提示词`：默认给英文版，可直接用于生成图
- 详情页标题尽量短（优先 10-14 字），避免一行放不下

### 4. 总结页

目标：
- 用一句话收拢全文
- 把“方法 / 流程 / 结构”压缩成易记结论
- 可加入一张总览图或闭环图的说明

## 文案风格规则

- 中文输出，适合小红书语境
- 句子短、信息密度高、少废话
- 默认按“可直接贴进设计稿”的风格写
- 默认更偏“小红书爆款风”，优先强化钩子、痛点、反差感和结论感
- 默认优先使用第一人称口吻来写文案，如“我最近在想 / 我会把它理解成 / 我越来越觉得”，增强分享感和个人表达感
- 默认避免使用“这篇文章 / 本文 / 这份内容 / 作者提到”这类转述型表达；除非用户明确要求保留资料综述口吻
- 用户如果觉得“太挤”，优先缩短标题和总结，不牺牲核心逻辑
- 详情页如果用于图片排版，优先压缩 `内容` 字数，而不是继续堆解释；宁可更短，也不要把单页写得发满发挤
- 用户如果强调“专业感”，总结中应加入专业术语或方法名
- 用户如果强调“别太学术”，优先保留结论和例子
- 如果用户没有指定风格，优先输出“爆款风里保留专业感”的版本，而不是平铺直叙的课程笔记风

## 发布文案规则

发布文案默认包含：
- `标题备选 3-5 个`
- `正文可直接复制版`
- `标签建议`

正文要求：
- 明显分段，适合手机端阅读
- 默认加入少量小表情（如 🤔📌✅🚀），增强可读性
- 表情数量保持克制，通常每 2-4 段出现 1 个即可
- 开头先给痛点或反差
- 中间讲核心观点或方法
- 结尾可自然收束，不使用“评论区打xx/私信我/关注领取”等引导互动话术
- 避免平台敏感表达，优先中性、信息型结尾
- 默认以“我”的分享口吻输出，优先写成个人观点整理、个人理解和个人结论，而不是资料转述

标签要求：
- 标签前缀固定为：`#且曼Ai产品经理就业班 #求职 #就业 #AI`
- 其后可按主题补充笔记类/专业类标签
- 输出标签时，固定前缀必须放在最前面，不可打乱顺序

## 合规要求（默认开启）

- 不写“评论区打xx”“私信领取”“关注领取模板”等导流式话术
- 不使用夸张承诺、绝对化收益、明显诱导互动表达
- CTA 仅可用中性表达，如“欢迎交流”“可继续讨论具体场景”

## 配图提示词规则

默认输出英文 prompt，适用于图像生成模型。

要求：
- 插图默认不含任何文字（必须包含 `Absolutely no text` 的完整约束）
- 提示词必须跟在对应详情页内容里，便于逐页对照，不要集中汇总
- 优先统一风格，先给母提示词，再给各页具体场景
- 明确 `Absolutely no text`，防止图片带字
- 默认插图区域尺寸：`891x721 px`（约 `5:4` 横图），并保留 `~10%` 边缘安全留白
- 如用户给了参考图/模板，以参考图的版式与质感优先
- 如果是同系列多张图，要提醒使用同一风格锁

建议结构：

```text
<STYLE SENTENCE>
Absolutely no text anywhere in the image: no words, no letters, no numbers, no labels, no captions, no logos, no watermark.
Scene: ...
Avoid: ...
```

常用约束：

```text
Absolutely no text anywhere in the image: no words, no letters, no numbers, no labels, no captions, no logo, no watermark.
```

### 默认插图风格（可按用户调整）

当用户未指定插图风格时，默认采用更适合小红书种草分享的风格句（可直接复用到每页 prompt 的第一行）：

```text
Xiaohongshu share-post illustration, cozy scrapbook collage style, warm creamy background, pastel sticker and paper-cut elements, subtle grain texture, soft shadows, cute but premium, airy whitespace, minimal clutter, landscape image area size 896x720 px (close to 5:4 aspect), keep ~10% safe padding around edges, consistent camera angle and rendering.
```

### 自动生图模式（APIMart / GPT-Image-2）

当用户明确要求“直接生图 / 保存到本地 / 不只要 prompt”时，除了输出文案和 prompt，还应走本地自动生图流程：

1. 先正常生成并落盘分享稿 markdown
2. 再使用当前工作目录下的脚本 `apimart_xhs_image.py`
3. 脚本会先调用 APIMart 兼容接口生成英文 prompt，再调用 `gpt-image-2` 生图
4. 生成结果默认保存到 `<稿件文件名>_images/`
5. 每张图会同时保存：
   - `.png` 图片
   - `.prompt.txt` 最终 prompt
   - `.json` 页级元数据
   - `manifest.json` 总清单

默认环境变量：

```bash
APIMART_API_KEY=...
APIMART_BASE_URL=https://api.apimart.ai/v1
APIMART_TEXT_MODEL=gpt-4o-mini
APIMART_IMAGE_MODEL=gpt-image-2
APIMART_IMAGE_SIZE=1280x1024
APIMART_IMAGE_QUALITY=medium
```

默认调用方式：

```bash
python3 apimart_xhs_image.py --markdown "/absolute/path/to/分享稿.md"
```

注意：
- 不要把真实 API key 直接写进 markdown、prompt 或 skill 文案里
- 默认从当前工作目录 `.env` / `.env.local` 读取 `APIMART_API_KEY`
- 如果用户给的是单页需求，也可以直接用：

```bash
python3 apimart_xhs_image.py \
  --title "页面标题" \
  --content "页面内容" \
  --summary "总结1" \
  --summary "总结2" \
  --summary "总结3"
```

## 工作流程

当用户提供主题或素材时，按以下顺序工作：

1. 先判断用户要做的是：
   - 单页内容
   - 多页分享
   - 标题/正文优化
   - 配图 prompt
   - 完整发布包
2. 提炼一个“主论点”
3. 设计页序
4. 产出逐页文案
5. 在每页内容后紧跟该页插图 prompt
6. 产出发布标题和正文
7. 默认落盘为 markdown 文件，便于记录与复查
8. 如果用户明确要求直接生图，则继续调用 `apimart_xhs_image.py` 生成图片并保存到本地

## 输出优先级

如果用户信息不足，优先补齐以下内容：
- 主题是什么
- 想做几页
- 有没有参考内容/链接/截图
- 更偏专业风还是爆款风

如果用户没有补充，也可以基于现有信息先给一版“可发布骨架”。

## 文件输出规范（默认）

- 默认在当前工作目录输出一个 `.md` 文件
- 文件名建议：`<主题>_小红书发布稿.md`
- 文件内容顺序：
  1. 封面与导读
  2. 逐页详情（每页文案后紧跟该页插图提示词）
  3. 发布标题候选
  4. 发布正文
  5. 标签建议

## 额外注意

- 用户常常会反复微调“标题长度、换行、排版感”，需要快速给更短版本
- 用户如果说“拥挤”，优先缩短标题、压缩句长、保留三点总结
- 用户如果说“风格不统一”，优先统一所有 prompt 的风格锁，不要每张图风格都重写
- 用户如果给了参考文档、截图或文章内容，必须尽量把案例映射到具体内容，而不是泛泛写方法论
